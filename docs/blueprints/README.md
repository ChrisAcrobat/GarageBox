# Blueprints

Visual and audio experiment and reference pages for GarageBox - Music Sandbox. Local only; not published to GitHub Pages. Light-blue blueprint theme (`css/style.css`, `favicon.svg`).

## Open

**Preferred:** open [`garagebox.code-workspace`](../../garagebox.code-workspace) with the VS Code **Live Preview** extension (`ms-vscode.live-server`). On start:

- Live Preview servers, one per workspace folder, App first: App `http://127.0.0.1:5500/` (`src/`, WS `:5501`), Blueprints `http://127.0.0.1:5502/` (`docs/blueprints/`, WS `:5503`). Each server uses HTTP N and WebSocket N+1, hence 5500/5502. The Repo folderOpen task starts them with `livePreview.start.preview.atFileString` using **relative** paths: `index.html` → App (Repo has no root `index.html`; App is listed before Blueprints), `meta.json` → Blueprints (it exists only in this folder). It then opens the catalog `http://127.0.0.1:5502/`. Absolute `${workspaceFolder:…}` paths were dropped because Live Preview resolves them to the first folder (Repo), so `:5502` never listened; running the folder tasks via `workbench.action.tasks.runTask` was dropped because it raised a confirmation prompt and timed out. The folder-scoped tasks **`Live Preview: App`** (`src/.vscode/tasks.json`) and **`Live Preview: Blueprints`** (`.vscode/tasks.json` in this folder) remain for manual use. Per-folder `.vscode/settings.json` pins `livePreview.portNumber` (App `5500`, Blueprints `5502`). Requires the extension, **Developer: Reload Window** after installing it, and opening `garagebox.code-workspace` (not the folder alone).
- App is still started first (for the ports), but the start task only waits until `http://127.0.0.1:5502/` returns a page containing `GarageBox` before it opens Blueprints; if App fails to start it just warns and Blueprints opens anyway (the catalog shows App as red **not up yet**)
- **Blueprints** opens in the **integrated** browser (`workbench.action.focusFirstEditorGroup` first, since the Live Preview starts leave Group 2 active, then `workbench.action.browser.open` with `openToSide: false`, then `workbench.action.moveEditorToFirstGroup`, since focus + open alone still landed beside in Group 2; reused if already open). The workspace forces `livePreview.openPreviewTarget: "Embedded Preview"` and `livePreview.useIntegratedBrowser: true`, so Live Preview does not open an external browser by default
- **App** stays available on `:5500`; its preview may flash briefly when its server starts, then Blueprints takes the integrated browser — use **Copy App link** / **Copy Blueprints link** on the catalog (App in an external browser for Web Audio)
- Analytics: same Google tag as the app (`js/analytics.js`)

**This folder alone (no Live Preview):** `python3 -m http.server 5502 --bind 127.0.0.1 --directory docs/blueprints` (from the repo root), then open `http://127.0.0.1:5502/`.

## Catalog

`index.html` reads `meta.json` (`blueprints` array: `name`, `title`, `comment`, `tags`, `ready`). Each blueprint lives in `{name}/`. The tag `needs-audio` means the page needs an external browser for sound. The sidebar filters by tag (Match any / Match all, tags sorted most used first, grey tags last) and by status (All / Ready / Draft). **Copy App link** and **Copy Blueprints link** are both verified: the URL must serve a page containing `GarageBox` (Blueprints `http://127.0.0.1:5502/` by fetch; App via `http://127.0.0.1:5500/garagebox-probe.html` (`src/garagebox-probe.html`): fetch first, then a hidden sandboxed frame whose inline script posts `{ command: 'garagebox-probe', title }` to the catalog, since the App server rejects cross-origin fetches — this works in an external browser too; Live Preview's `update-path` message remains a fallback). To test a red App check, stop the App server or point the check at a dead URL — don't move the App's `livePreview.portNumber` off `5500` (e.g. to `5510`), since Live Preview's HTTP N / WS N+1 pairing then breaks Blueprints as well. A small spinner shows while checking, **verified** fades after about 3.5 seconds, and a red **not up yet** stays and is retried every 4 seconds until the link is verified. Buttons stay enabled; a click re-checks and copies only a verified link. Paths are relative so the catalog works on its own port and under a repo-root server.
