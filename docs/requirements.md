# Requirements – GarageBox - Music Sandbox

Status: draft, under discussion.

## 1. Platform

- R1.1 The app is a website published on GitHub Pages (static files, no server).
- R1.2 The primary target environment is Chrome on Linux. Other browsers and operating systems should work where possible, but are tested second.

## 2. Controllers

- R2.1 The page detects which game controllers are connected.
- R2.2 If the controller is a regular gamepad, the user can choose which instrument it controls. The default is drums.
- R2.3 If the controller is a guitar controller, guitar is preselected.
- R2.4 Each connected controller becomes its own instrument.
- R2.5 The controller type is determined primarily from `gamepad.id`:
  - The XInput type in the name (Chrome/Edge on Windows), e.g. `GUITAR`, `GUITAR_ALTERNATE`, `GUITAR_BASS`, `DRUM_KIT`.
  - Vendor and product ID (Chrome: `Vendor: 1430 Product: 4748`, Firefox: `1430-4748-...`) matched against a list of known guitars and drum kits, taken from the Linux `xpad` driver's device table.
  - Keywords in the name, e.g. `guitar`, `x-plorer`, `drum`.
- R2.6 The user can always change the instrument manually, regardless of what the app detected.
- R2.7 All per-device settings (instrument, sound and every other per-device choice, plus any play state that changes how the device sounds, such as the locked range offset of R4.5.6) are stored per controller in the browser's local storage, so a device sounds the same after reloading the page (F5).
  - R2.7.1 Settings are always keyed by detected controller type and connection slot, e.g. "guitar, controller 1" (controller number as in R5.3.1). Different types on the same slot keep separate settings, so a gamepad and a guitar can both be used on slot 1 (not at the same time) without overwriting each other's settings. The detected type (R2.5) is used, not a manually chosen instrument (R2.6), so changing the instrument does not move the settings to another key.
- R2.8 Since the browser only exposes a controller after a button press, the app shows a prompt to press any button.
- R2.9 Each controller has its own advanced settings menu, where the user can change things like key, scale, note mapping and other instrument parameters. All settings have sensible defaults so the menu is never required to start playing.
- R2.9.1 Settings that are a number (for example mute fade-out, ring time, tilt smoothing, bend range) are number fields, not drop-down lists: the value can be typed in freely within the field's allowed range, and stepped up and down with the controller (R2.12). A typed value outside the range is set to the nearest allowed value; an empty or invalid entry goes back to the previous value. Settings that are a choice between named options (for example tone, octave, key, scale) stay drop-down lists.
- R2.10 A regular gamepad can be set to one of these instruments:
  - Drums (default, see section 4b).
  - Guitar: same notes and behavior as the Xplorer (section 4). Four face buttons plus one shoulder button act as the five fret buttons, the D-pad up/down acts as the strum bar, and the D-pad left/right do the D-pad action (R4.15). The other buttons (RB, the triggers, the sticks and stick clicks) stay unused.
  - Bass: same behavior as guitar, one octave lower, with a bass sound.
- R2.11 Further General MIDI instruments can be chosen in the advanced settings (R2.9).
- R2.12 The menus (start screen, a controller's advanced settings and its device information view) can be operated with that controller while the menu is open: D-pad up/down moves between the controls with a clearly visible highlight, left/right changes the value of the highlighted control, Start activates the highlighted control (presses a button, toggles a checkbox) and Back closes the menu (from the device information view, Back goes back to the settings). Each action has exactly one button: Start does not close a menu, left/right do not press buttons, and a Back press that closes a menu never also turns tilt on or off (R4.11.1). On a guitar controller (e.g. the Xplorer) the directions are turned 90 degrees clockwise, because that matches how the guitar is held: right moves down to the next control, left moves up to the previous one, and up/down (the strum bar, which is the same button as D-pad up/down) change the value, up forwards and down backwards. This applies to every menu operated by a guitar controller, also when it is set to play another instrument, but not to a regular gamepad in guitar/bass mode. Each controller only operates its own menu; during normal play the controls behave as before. The computer keyboard and the mouse keep working in the menus.
- R2.13 While a guitar's (or a gamepad's in guitar/bass mode) advanced settings are open as a controller menu (R2.14), pressing a fret plays its note at once without strumming, and releasing it stops the note, so sounds can be tried while changing them. Drums keep playing in the menu, except pads that share a button with the menu navigation.
- R2.14 R2.12 and R2.13 apply only when the settings were opened with Start on the controller. Settings opened with the mouse (or the keyboard) do not change how the controller plays: it keeps strumming, muting with the frets, turning tilt on and off with Back (R4.11) and playing all pads as usual, and setting changes still take effect immediately. Pressing Start on the controller while such settings are open turns them into a controller menu.

## 3. Sound

- R3.1 All sound is produced inside the browser, without recorded audio samples. Two kinds of sound source:
  - MIDI-style instruments: General MIDI instruments (e.g. guitar, drum kit) rendered by a synthesizer running in the browser.
  - Generated sounds: custom synthesized sounds built directly with the Web Audio API.
- R3.2 If both options work well, the sound source is selectable in the app.
- R3.3 MIDI-style instruments use the vendored library [webaudio-tinysynth](https://github.com/g200kg/webaudio-tinysynth) (Apache License 2.0), which synthesizes all General MIDI instruments without samples. Its license file is kept alongside the vendored copy.
- R3.4 Generated sounds are written for this project with the Web Audio API. The guitar uses plucked-string synthesis (Karplus-Strong), which also gives the natural decay required by R4.7.
- R3.4.1 The bass has its own generated bass sound, not the guitar's plucked string, so it sounds round and full like an electric bass played with the fingers: a soft thump when the note starts, a steady low tone, and a natural decay (R4.7). Mute fade-out (R4.3.1), the whammy (R4.5), tilt range shifting (R4.5.2 – R4.5.7), ring time and tone work the same way as for the guitar. The plucked string and the MIDI-style bass remain available as other sound sources for the bass.
- R3.5 Default sound source per instrument: guitar uses the generated plucked-string sound; bass uses the generated bass sound (R3.4.1); drums use the MIDI-style drum kit. The sound source can be changed per controller in the advanced settings (R2.9).
- R3.6 Guitar effects: every instrument except the drums can be given an effect sound in the controller's advanced settings (R2.9), so it can sound like an electric guitar through an amplifier. Choices: Clean (default, no effects, the sound as it is today), Crunch (light distortion and a small room) and Epic (heavy distortion, an echo and a large reverb, like a rock guitar on a big stage). The effects work with both sound sources and, like all other sound, are generated in the browser without recordings (R3.1). Choosing an effect must not make the instrument clearly louder than Clean.

## 4. Guitar (Guitar Hero Xplorer)

- R4.1 The guitar has five colored fret buttons. A note plays when a fret button is held and the strum bar is flicked up or down.
- R4.2 When the fret button is released, the note keeps ringing.
- R4.3 When the fret button of a ringing note is pressed again, that note is muted immediately on press-down. A new note only starts when the strum bar is hit.
- R4.3.1 Muting is a soft fade-out rather than a hard cut. The fade time is a setting (R2.9.1) with a default of 500 ms (long enough to sound like a soft stop and not click, short enough to stop a note like a hand laid on the string), and it can be set both shorter and longer. Note: the default is still being tried on the real guitar: 1000 ms was too long (2026-10-23), 250 ms too short (2026-10-24), and 500 ms is being tried now. Its field has a short plain-language hint below it that explains what it does (as for bend range, R4.5).
- R4.4 If the strum bar is hit twice without releasing the fret button in between, the note plays twice, possibly with a new pitch.
- R4.5 The whammy bar bends the pitch down: pressed all the way it lowers all ringing notes of the controller by a whole tone (−2 semitones), like a real whammy bar, which slackens the strings; pressed halfway it lowers them by half as much, and released the notes are back at their normal pitch. How far the whammy bends at full press (the bend range) is a number setting (R2.9.1). In the advanced settings the whammy can instead be set to change the volume or to do nothing. The tilt (the angle the guitar is held at, which is gradual on the Xplorer, see design 9.1) never changes the volume and never bends the pitch: it moves the guitar's playable range (R4.5.2 – R4.5.7). There is no vibrato option and no setting that gives the tilt a sound effect.
- R4.5.1 The tilt value is smoothed before it is used, so small shakes of the hand do not make the playable range jump (or a glide wobble, R4.14). The amount of smoothing can be changed in the controller's advanced settings (R2.9), including turning it off; the setting is shown on every controller with a tilt sensor. The device information view (debug view) keeps showing the raw value.
- R4.5.2 Tilt range shifting is turned on and off per controller with Back (R4.11). It is off when a controller connects and after the page is reloaded. Turning it on or off makes no sound of its own and shows no message; the simple view shows whether it is on (R5.6).
- R4.5.3 While tilt is on, tilting the neck moves all five fret buttons through the notes of the current key and scale. One *step* is one note of the scale. Tilting by 0.1 of the tilt range (the tilt value runs from 0 to 1) away from the angle the guitar was held at when tilt was turned on moves the frets by one step: neck up = higher notes, neck down = lower notes. For example, with E minor pentatonic (frets E3 G3 A3 B3 D4), two steps up the frets play A3 B3 D4 E4 G4 and one step down D3 E3 G3 A3 B3. With a scale of more than five notes the frets walk through all its notes (C major, two steps up from C3: E3 F3 G3 A3 B3). The sound moves in whole steps (unless tilt glide is on, R4.14). A step only changes once the tilt has moved a little past halfway to the next step (a small dead zone of 0.2 step, about 0.02 of the tilt range), so the notes do not flicker between two steps while the neck is held near the boundary.
- R4.5.4 Ringing notes keep their pitch when the range moves (unless tilt glide is on, R4.14); only notes started afterwards, strummed or tapped (R2.13), use the new range.
- R4.5.5 The range moves at most three octaves of the scale up or down from the normal range (15 steps for a five-note scale, 18 for the six-note blues scale, 21 for a seven-note scale); tilting further keeps it at the limit. The lowest and highest MIDI notes (0 and 127) are never passed.
- R4.5.6 Turning tilt off with Back locks the range where it is: the whole step the sound is using at that moment becomes the controller's new starting range (its *range offset*, a whole number of steps, 0 = the normal range). While tilt is off the frets keep playing that range at any angle. The range offset is saved with the controller's per-device settings (R2.7), so it survives a reload, and it stays the same number of steps when the key or scale is changed (so the actual notes follow the new scale). Turning tilt on again starts from the locked range and measures the tilt from the angle the guitar is held at that moment. The panel's "Reset to defaults" button (R2.9) sets the range offset back to 0; if tilt is on at that moment it stays on and is measured from the current angle again, so the frets are exactly at the normal range.
- R4.5.7 A controller without a tilt sensor (e.g. a regular gamepad in guitar or bass mode, R2.10) can still turn tilt on and off with Back, but its range never moves; it stays at its saved range offset (normally 0).
- R4.6 Notes on different frets ring independently. A strum only (re)triggers notes on frets that are held at that moment; other ringing notes keep sounding and are not renewed.
- R4.7 Ringing notes of the generated sounds (the plucked string, R3.4, and the bass sound, R3.4.1) decay naturally and get quieter over time, like a plucked string; how long they take to die away is the *ring time* setting (R4.7.1). Notes of the MIDI-style sounds (R3.3) keep the note length of their program: a decaying program such as a piano or a guitar dies away by itself, while a sustaining program such as an organ or strings keeps sounding at full level until the player stops it. On the guitar and bass a note is not tied to holding its fret (R4.2), so for a MIDI sound "held" means "not muted yet": a sustaining MIDI program on the guitar keeps sounding until it is muted by pressing its fret again (R4.3; the MIDI-style sounds end with their program's own release rather than the fade-out time of R4.3.1), restarted by a new strum (R4.4), or stopped by another player action such as a reset (R4.11.2), changing the instrument or sound, or closing the page.
  - R4.7.1 The ring time setting applies only to the generated sounds. Its field has a short plain-language hint below it that explains what it does and how it differs from the mute fade-out (R4.3.1). The MIDI-style sounds ignore it, and the ring time field is not shown in the advanced settings while the MIDI-style sound source is used (it shows again when a generated sound is chosen, with its saved value).
  - R4.7.2 Strum hold: on the guitar and the bass with a generated sound, the notes started by a strum stay at full level, without decaying, for as long as the strum bar is held after that strum. The ring time decay (R4.7) starts only when the strum bar is released. A quick strum (flicked and let go at once) sounds as before. Muting a note with its fret (R4.3) still works while the strum bar is held, and a new strum while it is held restarts the held frets' notes as usual (R4.4); the new notes are held too. With the MIDI-style sounds holding the strum bar has no extra effect (their notes already keep their program's length, R4.7). On the Xplorer the strum bar is the D-pad up/down, and on a regular gamepad in guitar or bass mode the D-pad up/down is the strum bar (R2.10), so holding it there works the same. While a controller menu is open (R2.12, R2.14) the strum bar navigates and holding it does nothing; notes that were being held when the menu opened start their decay at that moment. Notes played without a strum (tap-to-play, R2.13) are not held. The computer keyboard's guitar keys (R4c.3) hold the same way while Backspace is held.
- R4.8 If several fret buttons are held when the strum bar is hit, all of their notes play together as a chord.
- R4.9 By default the five fret buttons play the E minor pentatonic scale (green to orange: E, G, A, B, D). Key and scale (e.g. major/minor pentatonic, other keys) can be changed in the controller's advanced settings (R2.9).
- R4.10 Start opens the advanced settings (R2.9) for that controller. While they are open as a controller menu, Start activates the highlighted control and Back closes them (R2.12).
- R4.11 During play, Back turns tilt range shifting (R4.5.2) on or off for that controller. It acts when Back is released, not when it is pressed, and only if Back was held for less than 5 seconds (a longer hold resets the controller instead, R4.11.2). Back does not mute: ringing notes are muted by pressing their fret again (R4.3) or end by themselves as described in R4.7 (a sustaining MIDI program keeps sounding until muted). This applies to every controller playing guitar or bass, including a regular gamepad in guitar or bass mode (R4.5.7) and settings opened with the mouse (R2.14). On a lane playing drums a short press of Back does nothing.
- R4.11.1 While a controller's menu is open as a controller menu (R2.12, R2.14), and while the start screen is shown, Back only closes the menu. It never turns tilt on or off and never resets the controller: a Back press that was already going on when the menu opened is forgotten (it neither toggles on release nor counts toward the 5- and 10-second holds of R4.11.2 and R4.11.3), and the release of a Back press that closed a menu does nothing.
- R4.11.2 Holding Back for 5 seconds during play resets that controller's per-device settings (R2.7) to the defaults, but keeps the instrument it plays: a manually chosen instrument (R2.6) stays chosen, and a controller that plays its detected instrument keeps doing so. The reset happens as soon as the 5 seconds are reached, while Back is still held: ringing notes of that controller fade out (R4.3.1), tilt range shifting is turned off, the range offset goes back to 0 (R4.5.6), every other per-device setting (sound, key and scale, effect, fade time, tilt glide and so on) goes back to its default, and a short message "Settings reset" is shown in that controller's lane. Releasing Back afterwards does nothing (tilt is not toggled); holding on leads to the full reset of R4.11.3. Only that controller is affected; other controllers and the global settings (language, visual style, master volume and so on) stay as they are. This works on every controller with a Back button, whatever it plays, including drums, but not while a menu owns Back (R4.11.1). The *Reset to defaults* button in the advanced settings does the same as this 5-second reset (it also keeps the instrument), except that it leaves tilt on or off as it was.
- R4.11.3 Keeping Back held until 10 seconds (counted from the press, so 5 more seconds after the reset of R4.11.2) does a full reset of that controller: everything per-device goes back to the defaults, now including the instrument, which goes back to the one detected for the controller (R2.5; a regular gamepad goes back to drums). It happens as soon as the 10 seconds are reached, while Back is still held; ringing notes fade out, and a second short message "Full reset, instrument too" is shown in that controller's lane. Releasing Back afterwards does nothing. As for R4.11.2, only that controller is affected, the global settings stay, and it never happens while a menu owns Back (R4.11.1).
- R4.14 Tilt glide: a per-device checkbox *Tilt glides the pitch* (off by default) makes the pitch follow the tilt smoothly instead of in whole steps while tilt range shifting is on (R4.5.2). With it, each fret plays the note of its current step plus the same fraction of the distance to the next scale note: halfway between two steps it sounds halfway between the two scale notes (in semitones). Ringing notes glide too (R4.5.4 does not apply), each by its own amount, so a chord stays in the scale's shape. The whammy bend (R4.5) works on top of the glide, and the glide is not limited by the bend range. When tilt is turned off, all ringing notes and the range settle on the nearest whole step, which is locked as the range offset (R4.5.6); turning the checkbox off while tilt is on makes ringing notes settle on the current whole step. With glide on, the sound and the note strip (R5.7) always agree. The checkbox is shown only for a controller with a tilt sensor playing guitar or bass (not for drums, a regular gamepad in guitar or bass mode, or the computer keyboard's guitar keys), as the last row at the bottom of the advanced settings, below the *Device information* and *Reset to defaults* buttons. It is saved with the per-device settings, and a reset (R4.11.2) turns it off.
- R4.12 The Xbox (guide) button has no function, since browsers usually do not expose it.
- R4.13 The pitch range (octave) of the fret buttons can be changed in the controller's advanced settings (R2.9): Low (one octave down), Middle (default) and High (one octave up). This applies to the guitar and the bass, also in the gamepad guitar/bass mode (R2.10); Middle keeps the default ranges (guitar from E3, bass from E2).
- R4.15 D-pad action: during play (no controller menu open), D-pad left and right on a guitar or bass do an action chosen per controller in the advanced settings (R2.9), field *D-pad left/right*. On the Xplorer these are the D-pad left/right buttons beside the strum bar (its D-pad up/down is the strum bar); on a regular gamepad in guitar or bass mode they are the D-pad left/right (R2.10). Each press does one change (holding does not repeat). Choices:
  - Shift range one octave (default): left moves the five fret buttons one octave of the scale down, right one octave up (as many steps as the scale has notes, e.g. 5 for a pentatonic), within the limit of three octaves either way (R4.5.5); at the limit a press changes nothing. It changes the same locked range as tilt (R4.5.6), so it is kept like a range locked with Back; if tilt is on, it stays on and the tilt is measured again from the current angle. It does not change the octave setting of R4.13.
  - Change effect: left picks the previous, right the next effect (R3.6) in the order Clean, Crunch, Epic, wrapping around (right on Epic gives Clean).
  - Change key: left one semitone down, right one semitone up, wrapping around the twelve keys (B up gives C); the scale stays.
  - Change sound: steps through a short list of sounds for the instrument, wrapping around. Guitar: the plucked string, then the MIDI guitars (the default Electric Guitar (clean) first, then the other General MIDI guitars: Acoustic Guitar (nylon), Acoustic Guitar (steel), Electric Guitar (jazz), Electric Guitar (muted), Overdriven Guitar, Distortion Guitar, Guitar harmonics). Bass: the bass sound, the plucked string, then the MIDI basses (the default Electric Bass (finger) first, then Acoustic Bass, Electric Bass (pick), Fretless Bass, Slap Bass 1, Slap Bass 2, Synth Bass 1, Synth Bass 2). Other MIDI instruments can still be chosen in the settings; from such a choice, right goes to the first sound of the list and left to the last.
  - Off: D-pad left/right do nothing during play.
  Every change shows a short message in the lane, e.g. "Octave +1", "Crunch", "Key: D" or the name of the sound. The change is saved as the controller's normal setting (R2.7), shows in the advanced settings, and is undone by a reset (R4.11.2, R4.11.3). The action is only offered for the guitar and the bass: on drums the D-pad left/right are drum pads (R4b.1), and the computer keyboard has no D-pad. In the controller menus D-pad left/right keep changing values (R2.12).

## 4b. Drums (regular gamepad)

- R4b.1 Default mapping on a standard-layout gamepad:
  - The four right-side face buttons play kick drum, snare, hi-hat and tom.
  - The shoulder buttons play cymbals (e.g. crash and ride).
  - The analog triggers play drums whose hit strength (velocity) depends on how far the trigger is pressed.
- R4b.2 The exact assignment of sounds to buttons can be changed in the controller's advanced settings (R2.9).

## 4c. Computer keyboard

- R4c.1 The computer keyboard can act as an extra instrument, so the app can be tried and tested without a game controller.
- R4c.2 The keyboard instrument is hidden by default and can be turned on in the settings. When hidden, key presses do not play notes.
- R4c.3 Guitar emulation: keys `1`–`5` act as the five fret buttons (green to orange) and `Backspace` acts as the strum bar, with the same behavior as the Xplorer (section 4). Only with the Piano instrument (R4c.12).
- R4c.4 Melodic keys use the "musical typing" layout common in music software, based on a piano keyboard:
  - The home row (`A S D F G H J K L`) plays the natural notes (white piano keys), e.g. C D E F G A B C D.
  - The row above (`W E T Y U O P`) plays the sharps/flats (black piano keys), placed between the home-row keys they sit between, e.g. `W` = C#, `E` = D#.
  - The bottom row (`Z X C V B N M`) plays the same natural notes as the home row, one octave lower.
- R4c.5 When the keyboard instrument is visible, an on-screen keyboard shows the note name on each key that plays a note (with the Drums instrument, the drum sound instead, R4c.13).
- R4c.6 Like all instruments, a key lights up on screen while it is pressed.
- R4c.7 Key positions are based on physical key location (`KeyboardEvent.code`), so the layout works the same on Swedish and other keyboard layouts.
- R4c.8 Momentary octave shift, combined with R4c.4 (no setting needed; only with the Piano instrument, R4c.12):
  - While `Shift` is held, all melodic keys play one octave higher.
  - While `Alt` is held, all melodic keys play one octave lower.
  - The shift applies to notes started while the modifier is held; ringing notes keep their pitch when it is released.
  - `Ctrl` is deliberately not used, since browser shortcuts such as `Ctrl+W` (close tab) cannot be blocked by the page.
  - The app prevents the browser's default action for `Alt` (e.g. focusing the menu) while the keyboard instrument is active.
- R4c.9 Melodic keys behave like a piano: the note sounds while the key is held and stops (with a short soft release) when the key is released.
- R4c.10 `Space` acts as a sustain pedal: while it is held, released notes keep ringing as they naturally would (R4.7: generated sounds die away, a sustaining MIDI program keeps sounding); when it is released, all notes whose keys are no longer held stop. Only with the Piano instrument (R4c.12). The app prevents the browser's default action for `Space` (page scroll) while the keyboard instrument is active.
- R4c.11 The keyboard instrument's default sound is Acoustic Grand Piano from the MIDI-style instruments (R3.3). The sound can be changed in its advanced settings like any other instrument (R2.9).
- R4c.12 Instrument choice: in the keyboard's advanced settings (R2.9) the keyboard instrument plays *Piano* (sv "Piano"; default, the behavior of R4c.3 – R4c.11) or *Drums* (sv "Trummor", R4c.13). The choice is saved like the other settings (R2.7) and counts as the keyboard's instrument choice, so *Reset to defaults* keeps it. Changing it stops all ringing notes of the keyboard.
- R4c.13 Drums instrument: the musical-typing keys (R4c.4) play the MIDI drum kit (as R3.5 for drums) instead of notes: one drum sound per key, one-shot (the sound ends by itself, releasing the key does nothing), at a fixed strength. The sound of each key can be changed (or set to none) in the advanced settings like R4b.2. In this mode the octave shift (R4c.8), the `Space` sustain pedal (R4c.10) and the guitar keys `1`–`5` and `Backspace` (R4c.3) are off, and the settings that only apply to notes (sound source, MIDI program, effect, key, scale, mute fade-out, ring time) are hidden, as for drums. The lane shows drum columns like a drums lane, and the on-screen keyboard shows the drum sound on each key. Default mapping (kit layout: the home row is the main kit, the row above the cymbals, the bottom row extra sounds):
  - Home row: `A` kick (GM 36), `S` snare (38), `D` closed hi-hat (42), `F` open hi-hat (46), `G` pedal hi-hat (44), `H` high tom (50), `J` hi-mid tom (48), `K` low tom (45), `L` low floor tom (41).
  - Row above: `W` crash (49), `E` ride (51), `T` ride bell (53), `Y` Chinese cymbal (52), `U` splash (55), `O` crash 2 (57), `P` ride 2 (59).
  - Bottom row: `Z` kick (36, second kick for double-kick patterns), `X` side stick (37), `C` hand clap (39), `V` electric snare (40), `B` high floor tom (43), `N` tambourine (54), `M` cowbell (56).
- R4c.14 Numpad drum kit: while the keyboard instrument is on, in both Piano and Drums mode, the numeric keypad is a small drum kit laid out like a kit seen from above: `Numpad7` crash (49), `Numpad8` open hi-hat (46), `Numpad9` ride (51), `Numpad4` high tom (50), `Numpad5` snare (38), `Numpad6` low tom (45), `Numpad1` closed hi-hat (42), `Numpad2` kick (36), `Numpad3` low floor tom (41), `Numpad0` kick (36). Keys are found by physical position (`KeyboardEvent.code`, R4c.7), so it works whether NumLock is on or off. Hits are one-shot drum sounds like R4c.13, and each key's sound can be changed (or set to none) in the advanced settings like R4b.2. The app prevents the browser's default action for the numpad keys while the keyboard instrument is on. Laptops without a numeric keypad use the Drums instrument (R4c.13) instead.
- R4c.15 Numpad hits are shown in the keyboard lane as one-shot drum gems (also in Piano mode, next to the notes) and are recorded as part of the keyboard's track in a recording (F13.5).

## 5. Visuals

- R5.1 The screen shows which notes are being played.
- R5.2 The visual style is selectable:
  - Highway view: each played note appears at the player's end of a Guitar Hero-style highway and travels away from the player into the distance, the opposite direction of Guitar Hero (notes are not incoming targets, they are a trail of what was played).
  - Simple view: each controller has its own panel where the buttons light up and note names are shown while they play.
- R5.3 Each controller (instrument) has its own visual lane or panel. With several controllers connected, the lanes are shown side by side, like multiplayer Guitar Hero.
- R5.3.1 Above each lane the app shows the controller number (e.g. "1", "2", matching `gamepad.index` + 1) and the lane has its own color.
- R5.4 In the highway view, a ringing note is drawn as a long trail (sustain line) from its start for as long as it sounds. The trail fades in step with the note's volume (decay, fade-out, mute) and ends when the note stops.
  - R5.4.1 Where note marks or trails overlap in the highway view, newer notes are drawn on top of older ones.
  - R5.4.2 A trail lasts exactly as long as its note can be heard, for every sound. A sound that keeps playing until it is stopped (e.g. a MIDI organ held down) keeps its trail until the sound has gone silent; the trail never ends earlier because of an assumed decay time, and the ring time (R4.7.1) never shortens a MIDI note's trail. On the guitar and bass a MIDI note counts as held until it is muted (R4.7), so a sustaining program's trail stays at full opacity until the fret is pressed again.
  - R5.4.3 When a trail ends, its near end glides away at the same speed as the rest of the highway (note marks, trails, cross lines); it never jumps or jerks.
  - R5.4.4 The far end of the highway has no visible edge or border: the road looks as if it continues past the edge of the screen.
  - R5.4.5 Pitch bend from the whammy bar is visible on the trail, so the part of the trail played while bending looks different from the rest: the trail gets thinner the further the whammy is pressed, and at full whammy it is 20 % (a fifth) as thick as with the whammy released (half whammy: 60 %). The owner chose 20 % on 2026-10-24 after testing on the real guitar (tried before: about 50 % was too little a change, 10 % (2026-10-23) was too thin, 25 % looked good, 20 % chosen).
- R5.5 Star power: when a guitar with a whammy bar and a tilt sensor (e.g. the Xplorer) is held with the neck pointing up and the whammy bar is pressed all the way at the same time, star power starts on that controller's lane. Star power is only a visual effect: confetti rains over the lane and the lane's light changes, in both visual styles. Star power lasts as long as the neck is held up (the whammy bar may be released). When the neck is lowered, a countdown of about 8 seconds starts, and star power ends when it runs out. If the neck is raised again before that, star power continues and the countdown starts over the next time the neck is lowered. The countdown is not shown on screen. Star power adds no sound change of its own: the whammy bar keeps doing what it is set to do (R4.5) and, if tilt range shifting is on, raising the neck keeps moving the range (R4.5.3), exactly as without star power. Star power only uses the neck-up position (the tilt counted as pressed, design 3.1), not tilt range shifting: it starts and lasts the same whether tilt is on or off (R4.5.2), and whatever the whammy is set to do. After star power has ended, it starts again only the same way it started the first time (neck up and whammy bar fully pressed). It can be turned off in the controller's advanced settings (R2.9). A more complete star power design is separate future work (F11).
- R5.6 In the simple view, the tilt control of a guitar lane shows whether tilt range shifting (R4.5.2) is on or off and the current range offset in steps, e.g. "Tilt: on · +2 steps" or "Tilt: off · 0 steps". While tilt is off the control is shown dimmed and does not light up or fill when the guitar is tilted.
- R5.7 The note names under the five fret buttons (the *note strip*) follow the playable range (R4.5.3) in both visual styles, on guitar and bass lanes and on the strip of the computer keyboard's guitar keys (R4c.3). While tilt range shifting is on, the names slide smoothly sideways with the tilt, also between whole steps: tilting the neck up moves them to the left, so the next higher scale note slides in from the right towards the orange fret while the lowest name slides out on the left, and tilting down does the opposite. Names fade out as they move past the outer frets. The strip shows where the range is heading before the sound changes; when tilt is turned off, the strip settles at once on the locked whole step (R4.5.6). If the system asks for reduced motion (`prefers-reduced-motion`), the names jump one whole step at a time (the step the sound uses) instead of sliding. There is no separate range badge and no message when tilt is turned on or off.
  - R5.7.1 When tilt glide (R4.14) is off, the strip follows the tilt directly while the sound waits for the dead zone of R4.5.3, so near a step boundary the strip can be up to about 0.7 of a step ahead of the notes the frets play. This is accepted: the strip stays smooth, and as soon as the sound changes step, or tilt is turned off, both agree again. With tilt glide on, strip and sound always use the same value.
- R5.8 Orientation bars: short bars in the yellow fret color under some names of the note strip show where the middle of the key is. The *reference note* is the note of the middle (yellow) fret in the normal range (range offset 0) for the current key, scale and octave setting, e.g. A3 with the default E minor pentatonic. Every name in the strip with the same note letter as the reference note (the same pitch class) gets bars: one bar for the reference note itself, and one more bar for each octave away from it (A3 = 1 bar, A2 and A4 = 2 bars, A1 and A5 = 3 bars). Other names get none. The bars move and fade together with their name, the reference note does not move with the tilt or the locked range, and it is worked out again when the key, scale or octave setting changes. The strip always keeps room for the bars, so nothing below it moves while the names slide.

## 5b. Name

- R5b.1 The app is called **GarageBox - Music Sandbox** (short form "GarageBox"). This name is used in the page title, the app title (`app.title` in `lang/common.json`) and the titles of the test pages. The tagline "Your controllers are the band." may be shown on the start screen.
- R5b.2 The README states that the project is inspired by Apple's GarageBand and is not affiliated with Apple.

## 6. Language

- R6.1 All project documentation is written in English.
- R6.2 If the app supports multiple languages, UI texts are split into one JSON file per language, plus one shared file for words that are the same in every language (if any).
- R6.3 Note names: there are two sets of note names, the international names (C C# D D# E F F# G G# A A# B) and the names used in the current UI language. Each language file defines its own set. If the language's set is the same as the international one (as in English), no setting is shown and the international names are used. If they differ (as in Swedish, where B is called H), a global setting "Note names" lets the user choose between the two, with the international names as the default. The choice applies everywhere note names are shown (lanes, highway, on-screen keyboard, settings) and is saved like the other settings.

## 7. Technology and deployment

- R7.1 The app is written in plain JavaScript (ES modules), HTML and CSS, loaded directly by the browser. No build step and no Node.js tooling.
- R7.2 Third-party libraries, if any, are vendored into the repository as static files (no package manager, no runtime CDN dependency).
- R7.3 Deployment to GitHub Pages is done by a GitHub Actions workflow that publishes only the files the app needs. All app files live in a `src/` folder and the workflow publishes exactly that folder; `README.md`, `docs/`, `tests/` and other non-app files stay outside `src/`. The workflow itself must not require Node.js-based build tooling.

- F10 A more advanced plucked-string sound (R3): better tuning of high notes (e.g. allpass interpolation instead of linear interpolation in the delay line) and a choice of where the string is plucked (pick position, which changes the tone from round to twangy).
- F11 A fuller star power design (R5.5): e.g. how it is earned, longer or stronger effects, effects that follow the music.
- F12 Named presets: the user can save a controller's settings under a name and open a saved preset later. These named presets are separate from the unnamed settings that are saved automatically on every change (R2.7) and restored on reload. Resetting a controller's settings (by holding Back for 5 seconds, R4.11.2, or with *Reset to defaults*) restores the most recently opened named preset, or the defaults if none has been opened, but keeps the instrument the controller plays; the full reset (holding Back for 10 seconds, R4.11.3) always goes back to the defaults, including the detected instrument, whatever preset was opened. Neither replaces anything but the unnamed saved settings, and neither changes a named preset.
- F13 Recording: the players can record what they play, replay it with all lanes, make simple edits, keep versions, and export it. Not a current requirement; this describes the owner's idea in enough detail for a later design (sketch in design 13.1).
  - F13.1 Start: a *Record* button (sv "Spela in") in the top bar with a red recording light (a red dot/lamp icon) next to the text; while recording, the light glows (e.g. pulses) and the button reads *Stop* (sv "Stoppa"). Keyboard shortcut: `Ctrl+R`, and on macOS also `Cmd+R`. The app prevents the browser's default action (reloading the page) for this shortcut. It works only while the page has the focus, also while the keyboard instrument is on (keys pressed with `Ctrl` or `Cmd` are never notes, R4c.8) and while a form field has the focus. `Ctrl+Shift+R` (hard reload) and `F5` are left to the browser. When idle the shortcut opens the record dialog (F13.2); while recording it stops (F13.6); while the dialog is open it does nothing.
  - F13.2 Record dialog: before recording, a dialog asks for the recording name (prefilled, e.g. "Recording 2026-10-22 23:44"), the tempo in BPM (number field, default 120, range 30–300) and the time signature as beats per bar (number field or select, default 4, i.e. 4/4; the beat unit is always a quarter note) and the count-in, *Count-in* (sv "Inräkning"): a select with 0, 1, 2 or 4 bars, default 1 bar, labelled "None" / "1 bar" / "2 bars" / "4 bars" (sv "Ingen" / "1 takt" / "2 takter" / "4 takter"). Its last choices, including the count-in, are remembered for the next recording (saved like the other settings). The dialog has *Start* and *Cancel*; it can be operated with a controller like the other menus (R2.12).
  - F13.3 Count-in: after *Start* there is a count-in of whole bars, the number chosen in the record dialog (F13.2, default 1 bar), at the chosen tempo and time signature, before the music is meant to begin; its length follows from those (e.g. 1 bar of 4/4 at 120 BPM = 2 seconds). Recording has already started when the count-in starts: anything played during the count-in is recorded too. The count-in is played by drumsticks: the MIDI drum sound *Sticks* (General MIDI percussion note 31) clicks once per beat (the first beat of each bar a little louder), starting at once on *Start*, so 1 bar gives 4 clicks in 4/4 and 3 in 3/4, together with a visible count (e.g. a large beat number). The first bar of the music begins right after the last count-in bar, where the drumsticks stop. With a count-in of 0 bars there are no drumsticks: the music, and the metronome on beat 1, start at once on *Start*.
  - F13.4 Metronome: after the count-in a metronome starts exactly on beat 1 of the first bar after the count-in (at once with 0 bars, F13.3) and keeps the beat for the rest of the recording, with a sound that is clearly a metronome and different from the drumsticks: *Metronome Bell* (GM note 34) on the first beat of each bar and *Metronome Click* (GM note 33) on the other beats, plus a beat flash. The drumsticks and the metronome are recorded as two tracks of their own (drumsticks track, metronome track), each with its own lane on playback.
  - F13.5 What is recorded: not audio, but everything needed to play the performance again: per controller (lane), the note events with their times (note on/off, pitch bend, tilt glide, whammy volume, strum hold), tilt on/off and range changes (so the note strip can be replayed), changes of effect, sound, key and other per-device settings made during the recording, and the full per-device settings at the start. Because playback synthesises the sound again, the instrument and sound of a recorded track can be changed afterwards.
  - F13.6 Stop: pressing *Stop* (the record button, or `Ctrl+R` / `Cmd+R`, F13.1) ends the recording; the recording is then saved at once (F13.9) and opened in the playback view, so nothing is lost if the page is closed afterwards.
  - F13.7 Playback: a recording can be played (Play/Pause, Stop, and a position bar to jump to a time). On playback every recorded track is shown as a lane (highway or simple view, like live play) with the notes, trails, note strip and button presses as they happened, including the drumsticks and metronome tracks. Both have a clear mute button and are muted by default on playback (their beats are still shown in their lanes); the choice is saved with the project. Live controllers stay playable during playback (playing along), but are not added to the recording.
  - F13.8 Editing (simple tools, each undoable until the project is saved):
    - Trim: cut away time at the start and/or the end of the recording (e.g. the count-in bars). Notes that start inside the removed part are removed; notes that started before the new start and still ring are cut.
    - Per-track volume and mute.
    - Per-track instrument and sound: change the instrument of a recorded guitar, bass or keyboard track (e.g. guitar to bass, a different MIDI instrument, another effect); the recorded notes stay the same. A drums track keeps its drum kit, but its drum sounds can be reassigned like R4b.2; the same holds for the drum hits of a keyboard track (Drums instrument and numpad kit, R4c.13, R4c.14), while its piano notes can change sound as above.
    - Move a group of notes: select notes of one track in a time range and move them earlier or later (optionally snapping to the beat grid); their pitch bends, glides and note ends move with them.
  - F13.9 Saving and versions: recordings are stored in the browser (IndexedDB), never uploaded. Saving a project stores a new copy (version) with a reference to the version it came from; existing versions are never changed. The list of saved projects shows only the latest version of each project, with a way to open its history and go back to (open, and save on from) an older version. Deleting a project removes all its versions after a confirmation. A project can be renamed.
  - F13.10 Export, if possible: WAV and MP3 (the sound rendered again from the recorded events, with the current track volumes, instruments and mutes; muted tracks, e.g. the drumsticks and metronome tracks while muted, are left out, also from MIDI) and MIDI (a Standard MIDI File with one track per recorded track, the tempo and time signature, and program changes for the instruments). MIDI cannot carry the generated sounds, the effects or a different glide per string, so it is an approximation.
- F14 Backing tracks: a recording project (F13) can have one or more backing tracks, sounds that play along. Not a current requirement; sketch in design 13.2.
  - F14.1 Adding: the user inserts a sound by pasting a link (URL) to an audio file. The user can also choose a local audio file (owner approved), since many links cannot be used (F14.5). The project keeps a reference to the file on the computer, never a copy of it; this needs a browser that supports it (the File System Access API, e.g. Chrome and Edge). In other browsers (e.g. Firefox, Safari) the local file option shows "Your browser is not supported" (sv "Din webbläsare stöds inte") instead, and links still work. The browser may ask for permission to read the file again when the project is opened; if the user declines, the app says so and that backing track stays silent until permission is given (e.g. by pressing Play again and allowing it).
  - F14.2 Playing along: the backing tracks play when *Play* is pressed in a project and when *Record* is pressed (they start with the recording, i.e. during the count-in, F13.3), in time with the recorded tracks.
  - F14.3 Per backing track: an offset in seconds that either starts the sound later than the recording (positive) or skips the beginning of the sound (negative), a volume adjustment (e.g. −24 … +6 dB, default 0), mute and remove. Each backing track is shown in the project with its name (file name or link) and length.
  - F14.4 Saving and export: backing tracks are saved with the recording project and its versions (F13.9): a link as the link, a local file as a reference to the file only (F14.1), so the project does not work with that track on another computer or after the file is moved or deleted. When exporting, they are mixed into WAV and MP3 (with their offset and volume; a muted one is left out), but not into MIDI.
  - F14.5 Limits the user must be told about: a link only works if the server allows other sites to load it (CORS); otherwise the app says that the link cannot be loaded and suggests downloading the file and adding it as a local file (in a supported browser, F14.1). Pages of streaming sites (e.g. YouTube) are not audio files and cannot be used. A saved link can stop working later, and a local file is only found while it stays where it was. Local files need a supported browser (F14.1), and a declined read permission keeps that track silent. The user is responsible for having the right to use the sound; nothing is uploaded.
  - F14.6 Note for possible future work: storing a copy of the audio itself (as a Blob in IndexedDB) is not part of F14 today. It may still be needed later, e.g. if recorded vocals (sung or spoken audio from a microphone) are supported, since such audio exists only in the app and has no file to refer to. If that is added, backing tracks may use the same Blob storage too, e.g. as a fallback in browsers without file references.
- F15 Mobile instruments: when the page is opened on a phone (or another touch device), the phone itself can be used as an instrument, for example as maracas or as a microphone. Owner request of 2026-10-23; not a current requirement and not scheduled for a build yet (sketch in design 14.1).
  - F15.1 Mobile mode: the app detects a touch/mobile device (e.g. `pointer: coarse` together with motion sensor support) and offers the mobile instruments; the mode can also be chosen by hand, on any device, and left again. It works standalone in the phone's browser, without a computer or a game controller, and the sound plays on the phone.
  - F15.2 Sensor permission: motion sensors and the microphone are only used after a tap by the user (e.g. a *Start* button), because some browsers only allow the permission request from a user gesture (iOS Safari: `DeviceMotionEvent.requestPermission()`). If permission is refused or the sensor is missing, the app says so in plain words and the other instruments still work.
  - F15.3 Maracas: shaking the phone plays a shaker sound, detected from the accelerometer (`DeviceMotionEvent`). One shake (a sharp change of direction of the movement) gives one hit; holding the phone still gives no sound. The hit strength follows how hard the phone is shaken: a gentle shake is quiet, a hard shake loud. Like all sound the shaker is generated in the browser, without recordings (R3.1).
  - F15.4 Microphone: the phone's microphone can be used as an instrument (`getUserMedia`, which needs HTTPS, as GitHub Pages provides, and the user's permission). How the microphone is used is not decided yet (Q2). This is related to F6 (microphone input), which may share the same audio input code.
  - F15.5 The mobile view shows the chosen instrument large and easy to use with one hand, with a clear sign of whether the sensor or microphone is active, and gives visible feedback on each hit (e.g. a flash per shake), in the spirit of R5.1.
- F16 Phone pairing: a phone can be paired with a computer by scanning a QR code, which creates a direct connection between the two (WebRTC data channel through PeerJS or a similar library). The phone then acts as a remote controller for the computer, for example to give the computer a maracas controller. Owner request of 2026-10-23; not a current requirement and not scheduled for a build yet (sketch in design 14.2).
  - F16.1 Pairing: on the computer, a *Connect phone* button shows a QR code (and the same link as text, for copying) that holds the page URL with a pairing id, e.g. `…/?pair=<peer id>`. Scanning it with the phone camera opens the page on the phone, which connects to that computer at once, without typing anything. The pairing id is new for each page load and is not guessable.
  - F16.2 Remote controller: while paired, the phone sends what is played on it (e.g. maracas shakes with their strength, F15.3) to the computer, and the sound plays on the computer, not on the phone. A paired phone gets its own lane on the computer like a controller (R2.4, R5.3), with its own advanced settings (R2.9).
  - F16.3 Several phones can be paired with the same computer at once, each as its own instrument.
  - F16.4 Connection status is shown on both sides: on the computer (in the phone's lane and in the pairing dialog: waiting, connected, disconnected) and on the phone (connecting, connected to the computer, connection lost).
  - F16.5 Disconnect and reconnect: when the connection drops (phone screen locked, network change, page reloaded), both sides show it, the computer stops the phone's ringing sounds, and the phone tries to reconnect by itself with the same pairing id. A reconnected phone gets back its lane and settings. Either side can end the pairing.
  - F16.6 Latency: low latency is a goal, so the phone sends each event as soon as it happens, as small messages; the time from a shake to the sound on the computer should feel immediate (target to be measured on real devices).
  - F16.7 Technology: the connection library (PeerJS or similar) and the QR code generator are vendored as plain classic scripts in `vendor/`, like webaudio-tinysynth (R7.1, R7.2), with no build step. PeerJS by default uses a public signalling server (PeerJS Cloud) to set up the connection; only the setup goes through it, the played events go directly between the devices. Whether that external service is acceptable is open (Q3).

## Open questions

Tracked in the discussion; answered questions are moved into the requirements above.

- Q1 Twist/rotation: can the guitar's rotation (other than the tilt in R4.5) be read on any controller, and should it be smoothed like the tilt (R4.5.1)? To be tried out with the hardware later.
- Q2 Phone microphone (F15.4): how should the microphone be used? Options: (a) live audio input, the voice or sound played through the effects (R3.6) like an instrument; (b) pitch detection, turning singing or humming into notes of the current key and scale; (c) a percussion trigger, where a clap or tap on the phone plays a drum hit; or several of these as choices. For a paired phone (F16), option (a) would need an audio stream to the computer, not only small events.
- Q3 Signalling for phone pairing (F16.7): is the PeerJS public signalling server acceptable (an outside service the app depends on at pairing time, beside R1.1 "no server" and R7.2 "no runtime CDN dependency"), or should another way be used (own PeerServer, another free signalling service, or manual pairing without a server)? Also open: whether a TURN relay is needed for networks where a direct connection fails (e.g. some mobile networks), and which one.
- Q4 Mobile instruments beyond maracas and microphone (F15): should the phone also offer e.g. touch drum pads or a tilt-controlled instrument, and should a paired phone be able to play locally as well as on the computer?
